# Проверка игровых путей

Перечислять состояния и доступные действия, а не считать нажатые кнопки.
Проверять каждый различимый переход и следующий полезный шаг игрока.
Эквивалентные пути объединять; не создавать дублирующие крестики.

Для каждого окна:
- Есть одна явная безопасная кнопка возврата/отмены; Escape повторяет её.
- Основное действие, возврат, повторное открытие и вложенные переходы работают.
- После выхода можно выбрать фишку/сделать ход либо начать следующую партию.
- Отмена сохраняет поле, цели, ходы, помощников и прогресс.
- Содержимое и кнопки помещаются на маленьком и горизонтальном экране.

Обязательные сценарии:
- Победа: следующий уровень / книга; проигрыш: повтор / меню. Escape ведёт туда же, куда безопасная кнопка, без заблокированного поля.
- Помощники: выбор, отмена, применение, край поля, завершение уровня.
- Помощь и рецепты: каждая страница, вперёд и выход.
- Настройки, авторы, новая партия, выбор уровня, подтверждение сброса.
- Импорт: ошибка, отмена, подтверждение; экспорт и установка.
- Обновление и прерывания: каскад, сворачивание, возврат, перезагрузка, офлайн.
- Фактический результат и цель (например, 16 из 20), сохранение старых партий.

Автоматическая матрица реальных обработчиков: tests/dialog-routes.test.js.
Общий обработчик Escape/кнопок: tests/results.test.js.
Модель DOM в тестах не заменяет проверку настоящего интерфейса в Chrome и
на телефоне. В отчёте явно разделять автоматические, браузерные и непроверенные сценарии.
