# Garden Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Replace recipe collection with a persistent garden home screen and one star per new campaign victory.
**Architecture:** Pure garden economy module, DOM garden view with local illustrated assets, integration into existing single-page navigation and storage. Derive balance from completed levels and owned items to avoid duplicate reward bookkeeping.
**Tech Stack:** Vanilla JavaScript modules, CSS, Node test runner, local PWA assets.
**Spec:** docs/superpowers/specs/2026-11-16-garden.md

## Global Constraints
- No migration or compatibility layer; retain current gameplay and postcards.
- One explicit exit per modal; Escape follows it.
- Offline assets, relative URLs, no timers or payments.
- Build then check:release before tests; no public deployment.

## Review Focus
- Reopening victory or replaying a level cannot grant a second star.
- Double purchase and insufficient funds cannot lose stars or overwrite items.
- Failed storage and competing tabs cannot report a successful purchase.
- Small portrait and landscape screens retain all actions and targets.
- Garden/menu/game/results/update/reload paths retain purchases and active games.
