# Android Phase One Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement this plan task-by-task. Track actual verification and remaining work below.

**Goal:** Подготовить Android-приложение из существующей PWA, iOS оставить второй фазой.

**Architecture:** Общая игра в `dist/`; отдельная точка входа Android собирает Capacitor API, затем запускает тот же `app.js`. Нативные адаптеры отвечают за сохранения, жизненный цикл и отправку открыток. Сборка кладёт ресурсы в локальный пакет, PWA сохраняет свой service worker.

**Tech Stack:** JavaScript, Node 22+, Capacitor 8, Android/Gradle, esbuild для нативной точки входа.

**Spec:** ../specs/2026-11-16-mobile-design.md

## Global Constraints
- Текущий формат сохранений; без миграций, входа, рекламы, платежей, аналитики.
- PWA и GitHub Pages продолжают работать с относительными URL.
- После изменения dist: `npm run build`, `npm run check:release`, затем тесты.
- Не публиковать в магазины или Pages. Patch повысить один раз перед выдачей новой сборки.
- Открытки без рекламной ссылки; iOS только в плане второй фазы.

## Review Focus
- Ошибка чтения нативного сохранения не должна приводить к его перезаписи пустой партией.
- Несколько быстрых записей/сворачивание не должны менять порядок сохранений или скрывать сбой.
- Android Back во вложенном окне и после победы не должен оставлять нерабочее поле.
- Отмена отправки и недоступный получатель не должны ломать дальнейшую игру.
- Пакет не должен зависеть от сети или регистрировать PWA worker.
