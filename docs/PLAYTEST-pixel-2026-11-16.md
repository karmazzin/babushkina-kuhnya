# Проверка установленного APK на Pixel — 16 ноября 2026

Проверена версия 1.0.7 (1000007), debug APK, на физическом Pixel 10 / Android 17. Управление настоящим Android WebView через ADB/CDP; это не эмуляция телефона. Код приложения в ходе проверки не менялся.

## Сохранность прогресса

Перед изменениями сделана актуальная резервная копия SharedPreferences KitchenProgress. Более ранняя копия была заменена как контрольная после обнаружения новых действий пользователя до начала тестов. Контрольная партия: уровень 2, 24 хода, 0 действий; пройден уровень 1, рекорд 1670, одна открытка.

После каждого набора сценариев восстановлена точная исходная строка сохранения. Итоговая проверка после принудительного завершения и холодного запуска подтвердила совпадение строки через нативный мост и побайтовое совпадение XML на устройстве с резервной копией. SHA-256 XML: `e18e90b4a691b39036eeb7adc90fefa2d28307b658e06e506401b8a9732423e8`.

Исходные настройки ориентации восстановлены; удержание экрана при питании возвращено в 0. Все созданные ADB-forward удалены. Приложение оставлено в меню с исходной партией. Резервные копии и подробные свидетельства находятся локально в игнорируемом `build/pixel-qa/`, не включаются в репозиторий.

## Подтверждено на устройстве

- Ход двумя касаниями, запись результата; после переходов проверялся следующий полезный ход и изменение сохранения.
- Настройки → подтверждение сброса → системная отмена → настройки → поле. Сброс не выполнялся.
- Выбор помощника → системная отмена → обычный ход.
- Меню → книга → Android Back → продолжение партии.
- Открытка → нативное окно выбора приложения для отправки → отмена → коллекция → меню → продолжение. Сообщения не отправлялись.
- Home → возврат: сохранение не меняется, музыка получает pause и затем play, ошибок медиаплеера не зафиксировано; следующий ход работает.
- Принудительное завершение процесса → холодный запуск: сохранение совпадает, все типы плиток поля совпадают с сохранённым массивом; следующий ход работает.
- Отключение сети через CDP только для WebView → перезагрузка → продолжение → следующий ход. Радиомодули телефона не отключались.
- Победа → следующий уровень; победа → Android Back → книга → продолжение.
- Проигрыш → повтор; проигрыш → Android Back → меню → начало новой попытки.
- Последние помощники → отмена завершения попытки → применение помощника → подтверждение завершения → повтор.
- Угощение дня: повтор, выход и продолжение. Режим «Без спешки»: ход, выход и продолжение.
- Портрет 375×843 CSS px и альбомный экран 843×375: документ без прокрутки, поле помещается; в альбомном режиме видимые кнопки не выходят за границы экрана и работает следующий ход. Снимки обеих ориентаций просмотрены визуально.

Победа, проигрыш и состояние последних помощников проверялись с временными подготовленными сохранениями текущего формата, а не полным прохождением уровня с начала. Остальные ходы выполнялись на реальном поле установленного приложения. По завершении все тестовые изменения удалены восстановлением исходного сохранения.

В проверенных наборах navigation/lifecycle/results ошибок JavaScript не зарегистрировано. В собранных логах процесса не найдено `FATAL EXCEPTION`, `ANR in`, `Uncaught` или `AndroidRuntime`. Подтверждённых дефектов приложения в этих сценариях не обнаружено. Два ранних прерывания из-за блокировки экрана были устранены временным удержанием экрана; соответствующие сценарии затем завершились успешно.

## Остаётся проверить до выпуска

- Первый запуск после совершенно новой установки без сети: не проверялся, поскольку очистка данных текущей установки не входила в задачу. Холодный запуск существующей установки в авиарежиме проверен в дополнении ниже.
- Блокировка/разблокировка экрана, звонок, субъективная громкость и качество звука через динамик/наушники. Проверка событий Audio не заменяет прослушивание.
- Отдельный сценарий свайпов и длительная игровая сессия, полное прохождение уровня до победы/проигрыша.
- Доставка JPEG в настоящий мессенджер: проверены только открытие системного chooser и отмена.
- Обновление содержимого игры и установка с релизной подписью / через магазин. Замена APK с повышением Android versionCode и прежними игровыми ресурсами проверена в дополнении ниже.

Данная проверка не является публикацией в магазине или первым выпуском игрокам. iOS остаётся второй фазой.


## Дополнение: авиарежим и обновление APK поверх текущего

Повторная проверка выполнена 16 ноября 2026 по отдельному поручению пользователя. Перед началом снята новая контрольная копия: пользователь успел продвинуться до уровня 3, 21 оставшийся ход, 3 действия, рекорд 1670. Раннее сохранение уровня 2 для восстановления не использовалось.

Подготовлен изолированный APK `1.0.7-qa-update` с versionCode 1000008 вместо 1000007. Сборка Gradle завершилась успешно. Сертификат подписи совпадает с установленным debug APK; все 93 файла assets побайтово совпадают с исходным APK. Это проверка Android-обновления пакета, а не нового игрового содержимого или миграций. Исходники, package.json и пользовательский номер релиза не менялись.

Подтверждённые результаты:

- Реальный авиарежим включён; Wi-Fi и Bluetooth выключены. Android сообщил `Active default network: none`.
- После принудительного завершения процесса приложение запустилось без сети, загрузило точную сохранённую партию и позволило сделать ход (3 → 4 действия, 21 → 20 ходов).
- Повторный холодный запуск сохранил этот ход; следующий ход также прошёл (4 → 5 действий).
- После восстановления контрольной партии выполнен `adb install -r` тестового APK. Package Manager подтвердил versionCode 1000008. До первого запуска сохранение на диске побайтово совпадало с контрольным.
- Обновлённое приложение запустилось в авиарежиме; строка нативного сохранения и все типы плиток совпали с контрольными. Следующий ход и его сохранение после повторного холодного запуска прошли.
- Ошибок JavaScript в этих сценариях не зарегистрировано.
- После тестов восстановлены свежая контрольная партия и обычный APK 1.0.7 / 1000007 через поддерживаемую для debug сборок установку `-r -d`, без удаления приложения и очистки данных. После холодного запуска проверено побайтовое совпадение XML с новой резервной копией: SHA-256 `46ed0f818a9148e2bc90e4fdde700c56c816e36251a46c5754e01ee46f76c182`.
- Исходные настройки сверены: airplane_mode_on=0, wifi_on=1, bluetooth_on=1, mobile_data=1, stay_on_while_plugged_in=0. Созданные для проверки ADB-forward удалены.

Артефакты проверки находятся локально в `build/pixel-qa/network-update.json`, `network-update-baseline.json`, `network-update-baseline.xml`, `network-original-settings.json`. Они не включаются в репозиторий. Первая попытка остановилась на различии написания `Wifi` / `Wi-Fi` в выводе ADB; после исправления проверки повторный прогон полностью прошёл. Это не дефект приложения.
