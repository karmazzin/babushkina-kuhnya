# Android — первая фаза

Общая игровая база остаётся в `dist/`. PWA публикуется отдельно. Android использует Capacitor, локальный пакет ресурсов и `native/android-entry.js`; сеть для первого запуска установленной игры не нужна.

План: [Android, затем iOS](superpowers/plans/2026-11-16-android-phase-one.md). Дизайн: [мобильные приложения](superpowers/specs/2026-11-16-mobile-design.md).

## Требования и сборка

- Node.js 22+, `npm ci`.
- JDK 21 и Android SDK: platform-tools, Android SDK Platform 36, Build Tools 36.0.0. Android Studio — удобный, но необязательный способ установки.
- `JAVA_HOME` и `ANDROID_HOME` указывают на JDK и SDK. На этом компьютере временный локальный набор находится в игнорируемой `.android-tools/`; `scripts/run-android.mjs` находит его автоматически.

```sh
npm run android:apk
```

Команда пересобирает релиз PWA, проверяет хеши, упаковывает Android-ресурсы, синхронизирует плагины и вызывает Gradle. Debug APK: `android/app/build/outputs/apk/debug/app-debug.apk`. Проверенная копия 1.0.7: `build/releases/babushkina-kuhnya-1.0.7-debug.apk`. Это тестовая подпись; её не использовать как ключ публичного выпуска.

```sh
npm run android:open
npm run android:bundle
```

`android:open` открывает Android Studio. `android:bundle` создаёт неподписанный release AAB для последующей настройки подписи, а не готовую публикацию. Перед загрузкой в магазин отдельно определить окончательный applicationId и постоянный upload key; ключи/пароли не хранить в Git.

Технический applicationId: `io.github.karmazzin.babushkinakuhnya`. `versionName` берётся из `package.json.version`; `versionCode = major × 1000000 + minor × 1000 + patch`. Версия повышается через `npm run release:patch` один раз на выпуск. Генерируемый `android/app/version.properties` не редактировать вручную.

## Установка на телефон

Передать APK на свой Android и открыть его, разрешив установку из выбранного источника, либо при включённой USB-отладке:

```sh
adb devices
adb install -r android/app/build/outputs/apk/debug/app-debug.apk
```

Первая установка не читает сохранение браузерной PWA. Формат игры один, но хранилища изолированы. Обновление APK с тем же ID и ключом сохраняет данные; удаление приложения удаляет прогресс. Облачная синхронизация и резервное копирование ОС не включены.

## Устройство реализации

- `KitchenSavePlugin.java`: SharedPreferences с подтверждением `commit()` на потоке плагинов. Чтение обязательно до запуска игры; при ошибке/повреждении показывается повторный запуск без сброса данных.
- `native-storage.js`: кеш текущего состояния и последовательная очередь записи. Перед показом каскада ожидается подтверждение записи. При сбое показывается предупреждение, а последний снимок остаётся для повторной записи. Перед сворачиванием через «Назад» ожидается подтверждение; при ошибке приложение остаётся открытым.
- `native-sharing.js`: JPEG в приватном кеше `postcards/` и системное меню отправки. FileProvider открывает только эту подпапку; ссылки на игру нет.
- Android не регистрирует service worker, не предлагает установку PWA и не загружает новый код с GitHub Pages. Обновления — через установку новой сборки/магазин.
- Иконки и заставка сохранены в `android/app/src/main/res`. Перегенерация из существующего изображения: `python3 scripts/build-android-icons.py` (Pillow).

## Проверки

```sh
npm run build
npm run check:release
npm test
npm run android:prepare
node scripts/qa-android-web.mjs
```

Последняя команда использует установленный Google Chrome; другой путь задаётся `CHROME_PATH`. Она проверяет реальный HTML/CSS/JS и нативную точку входа с имитацией мостика Capacitor. Это НЕ проверка Java, Android WebView, звука телефона или установленного мессенджера. Снимки сохраняются в `build/qa-android/`.

Перед выпуском игрокам нужен реальный Pixel: первый запуск в авиарежиме; все три режима; победа/проигрыш и следующий ход; завершение процесса после хода; возвраты из окон; поворот; громкость, блокировка и сворачивание; отправка JPEG в мессенджер; обновление поверх предыдущей сборки без удаления данных. Фактический статус — в [отчёте](PLAYTEST-android-2026-11-16.md).

## Вторая фаза

iOS-проект пока не создан. После Android-проверки: Xcode, адаптер подтверждённых сохранений, Share/Filesystem, privacy manifest, реальный iPhone, TestFlight и материалы App Store. Аккаунты магазинов и публикация оформляются отдельным этапом.

Ручная CI-сборка: workflow `Build Android test APK` создаёт APK-артефакт, без публикации в магазины. На GitHub он станет доступен после отправки workflow в репозиторий. У CI временный debug key: такие APK могут требовать удаления прежней установки с другой подписью (с потерей её данных). Для проверки обновлений использовать локальные APK с одним ключом либо настроить постоянный ключ отдельно.

## Локальная релизная проверка

Подписанные release APK подготовлены и отдельная release-установка проверена на Pixel без публикации. Ключ, артефакты, сохранность основной партии и границы проверки: [релизная сборка](ANDROID-RELEASE.md).
